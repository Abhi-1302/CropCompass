## Remediation Results (23 October)

The implementation below supersedes the original findings as a status report, but **does not clear the weather
release blocker**. The original test record is preserved below.

- Added migration 0005: cell quality/revision metadata and resumable `weather_years` checkpoints.
- Calendar-year daily LST downloads, up to two concurrent POWER HTTP requests per process, retries honoring
	`Retry-After`, unit/date/coverage/missingness/physical checks, and daily-versus-monthly rainfall and EVLAND checks.
	Monthly rates are multiplied by calendar month length; tolerance is 0.011 mm per day plus 0.1 mm for rounding.
- Solar gaps before 1984 and recent product lag are explicit. Failed annual checks trigger month-sized requests;
	partial or not-yet-published recent months require an extra short-window match. Historical missing monthly checks fail.
- Entire histories publish atomically only after verification. Existing data is never divided by 24 or overwritten
	with a partial candidate. All dependent cache reads are gated, and dataset revisions invalidate derived results.
- Existing saved plans remain unchanged and are labelled unverified/outdated; new plans record their weather revision.
- Weather, soil and satellite have separate progress/source/date displays. Quarantine does not hide journal, soil
	editing, saved boundaries or warned saved plans. Refresh resumes interrupted work, including farms stuck pending.
- Corrected mobile overflow, boundary-derived area reset, farmer-soil labels, explicit fallow provenance/date labels,
	and translated journal residue. Farm tabs and planner modes persist in the URL.
- Tied/singleton score components are neutral internally and shown as unavailable comparisons, not perfect scores.
	Absolute losses and exact historical failure counts appear before comparative bars.
- Password reset now returns the same service-wide email/development/unavailable state for known and unknown users.
	Development explicitly says no email was sent; configured SMTP acknowledges a request, not confirmed delivery.

## Verdict

## Findings and Priorities

### P0: Full-history rainfall is 24 times the short-request values

At latitude 18.5, longitude 79.375, with `community=AG`, JSON format and the application's 17 parameters:

| Date | Request 19810101-20261022 | Request 20240701-20240702 |
| --- | ---: | ---: |
| 2024-07-01 | 259.44 | 10.81 |
| 2024-07-02 | 186.00 | 7.75 |

The full-history raw response, not just the database, reproduced these inflated values. Both responses advertise `PRECTOTCORR` as `mm/day`; the full response reports POWER API v2.10.1. A one-parameter short request and a 17-parameter short request agree, so the parameter list alone does not explain the difference. The precise upstream cause and affected date-range boundary remain unresolved.

Observed consequences: Warangal showed 17,218 mm since June and median annual rainfall of 22,563 mm; Iowa showed 23,336 mm year-to-date. Climate classification, soil water and crop advice therefore cannot be trusted for these new cells. Existing Telangana reference data matched a fresh short request for the sampled week.

Action: investigate request-range behavior with independently verified reference data; validate units and plausible values before marking ingestion Ready; quarantine suspect cells and suppress advice; repair/version cached data after the ingestion fix. Do not blindly divide all rainfall by 24, because existing cells and short requests can already be correct.

Owning paths: [POWER parser](../backend/engine/ingest/power.py#L75), [climate cache](../backend/app/services/climate_cache.py#L34).

### P1: Relative scores look like absolute safety

With current cotton occupying the field, the single remaining ranked Groundnut option displayed 100 for every pillar, including "Low risk", alongside "Fails 9 in 10 years" and negative typical profit. The failure display is rounded; this is not evidence that the exact 0.9 exclusion threshold is broken. The perfect score comes from normalization of tied/single-option values.

Action: label scores explicitly as relative comparisons, avoid perfect-looking singleton scores, and put absolute failure probability and losses ahead of the relative score. Consider warning styling or an unavailable relative score for a singleton set.

Owning path: [scoring](../backend/engine/planner/scoring.py#L18).

### P1: Mobile header and tabs overflow

At 390 px, document widths were 451 px (English), 417 px (Hindi) and 460 px (Telugu). Sign out was beyond the right edge; Telugu farm tabs also overflowed. Screenshot inspection confirmed clipping and horizontal page scrolling.

Action: use a compact mobile account menu, constrain the language selector, and make the tab row deliberately scrollable within the viewport or use a mobile view selector. Add automated overflow checks at 320/390 px in every language.

Owning paths: [header](../frontend/src/components/Layout.tsx#L47), [farm tabs](../frontend/src/pages/FarmPage.tsx#L133).

### P1: No functioning email delivery in this environment

`SMTP_HOST` was unset. The backend logged a reset link but sent no email, while the UI said a link was on its way. The token flow passed using the development log. Real delivery, inbox receipt and provider errors remain unverified.

Action: configure and test SMTP before release; surface delivery/configuration failures to operators and clearly label development mode. Preserve the generic public response to avoid account enumeration. Ensure the public reset-link origin matches the deployed origin.

Owning path: [mailer](../backend/app/services/mailer.py#L15).

### P2: Clearing a boundary retains its calculated area

After drawing and undoing, Clear displayed zero corners but retained the last derived area. Switching to pin mode can carry that stale area into a different location.

Action: track whether area was typed or derived, clear derived coordinates/area with the boundary, and prevent contradictory boundary/location edits. Show the saved boundary on the farm page so users can verify it later.

Owning path: [Clear action](../frontend/src/pages/NewFarmPage.tsx#L185).

### P2: Misleading soil provenance and Fallow messaging

- Farmer-entered capacity appeared as "standard value" in Crop fit, although Soil correctly said "Your values". Use the three-way soil source consistently. [Crop fit label](../frontend/src/features/crops/CropFitPanel.tsx#L243).
- An explicitly logged Fallow season removed the assumed crop but still produced "No crop is logged" and an update-journal prompt. Distinguish recorded Fallow from missing history. The Fallow form also still asks for sowing/harvest dates rather than start/end of the fallow period. [Soil-water note](../frontend/src/features/climate/SoilNowNote.tsx#L13).

### P2: Translation checks miss runtime catalog labels

The Telugu journal displayed `Left on surface (mulch)` in English. Key completeness passes because this text comes directly from the English API catalog.

Action: route all catalog labels through the translation helper and add rendered-page assertions; review agronomic terminology with native speakers. [Journal residue label](../frontend/src/features/history/HistoryPanel.tsx#L195).

## Further UX Improvements

- Expose separate weather, soil and satellite status, progress and last-updated dates. "Ready" currently does not mean every source is complete or trustworthy.
- Reduce visual density: show three recommendations first, expand details on demand, and present failure probability and expected losses before scores and technical metrics.
- Offer hectare/acre units, explain irrigation assumptions, and use user-friendly soil-test terminology while retaining units and provenance.
- Preserve selected farm tab and planner mode in the URL so refresh and browser navigation retain context.
- Keep destructive actions away from routine controls; use accessible confirmation dialogs with the farm/plan name rather than generic browser confirms.
- Add clear download completion feedback and field-level save/error feedback.
- Improve map ergonomics with a visible draw-complete action, clearer vertex handles, stable behaviour during animated zoom, and a recoverable tile/search failure state.
- Test keyboard navigation, screen readers, reduced motion and real touch devices. The viewport test is not a full accessibility audit.
